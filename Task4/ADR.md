### <a name="_qmphm5d6rvi3"></a>**Решение**

[Диаграмма контекста](./Context.puml)

[Диаграмма контейнеров](./Containers.puml)

Система кол-центра получает информацию по депозитам с помощью синхронного запроса в сервис депозитов.
Сервис депозитов хранит актуальные данные по депозитам в своей БД. При получении из Кафки обновленных данных, информация
в БД обновляется.
Из-за невозможности предоставлять файлы с информацией по депозитам во внешний кол-центр через API, при обновлении
информации по депозитам формируется файл и отправляется по почте.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

Размещать файл с информацией о депозитах на сайте банка. Тогда менеджер внешнего кол-центра может скачивать файл с сайта.
Минусы решения:
1. Отсутствует информация о возможности посещения менеджером внешнего кол-центра сайта банка.
2. Необходимо ограничивать возможность скачивания файла с информацией о депозитах остальным пользователям
3. Менеджер внешнего кол-центра будет получать новую информацию о депозитах по факту обращения к сайту, а не по факту изменения информации. Информация о депозитах может стать неактуальной.

**Недостатки, ограничения, риски**

Если менеджер внешнего кол-центра не сможет получить письмо с обновленной информацией о депозитах (сбой почтовой службы), данные могут оказаться неактуальными.
Со стороны внешнего кол-центра отсутствует информация, что последние присланные данные являются актуальными, и не было неудачных попыток получения новых данных.
